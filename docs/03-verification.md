# 验证记录

日期：2026-10-20。环境：Windows、Node 24.17.0、Vite 6.4.4、Vitest 5.0.5、Chromium 1248。运行时网格映射、提色、图纸检测和路线计算由 Worker 执行。

- `npm test`：11 个测试文件，51 个测试通过。
- `npm run build`：TypeScript、Vite、PWA 构建通过；Worker 11.84 KB，主 JS 约 428 KB（gzip 约 126 KB），帮助面板按需分包为 48.23 KB（gzip 18.31 KB），15 项离线缓存约 733 KiB。
- 算法回归：CIEDE2000 参考值、快速匹配与暴力匹配等价；50×50 / 100×100 映射；抖动、透明、锁定和调色板闭包；三种路线覆盖全部有效格子且无重复遗漏。
- `npm run test:e2e`：真实 Chromium Worker、100×100、用户 JSON 色卡、图片色卡、单格改白、撤销/重做、PNG/CSV/打印 PDF、完整备份、进度与手工改色跨页面/恢复/刷新保留、离线刷新、暗色、390×844 手机视口、真实双指触控缩放和缩放按钮均通过。附加延迟 Worker 回包，在转换进行中改名，验证旧结果拒绝后自动重试；删除备份 mappingKey 模拟旧 schema v1，验证恢复不会覆盖手工格与进度。页面异常 0、外部资源请求 0。
- `npm run test:features`：本地离线词典、专家模式长按/搜索/复制、步骤跳转与滑动预览、单次原子撤销、跨页面完成历史、框选批量、暂停/键盘、刷新后偏好记忆、手机非模态布局均通过；外部请求 0。
- `npm run test:image-flow`：在开发服务（默认5173）验证 StrictMode 重挂载后的实际 Canvas 着色像素；覆盖导入时延迟 Worker、立即切换路线规划、返回编辑、原图切换、50×50→100×100 和手机窄屏。修复前路线网格虽有2500颗豆子，Canvas仍为默认300×150透明画布；修复绘制帧清理后画布正确重绘。首次映射现在在导入页完成后保存，避免编辑页卸载留下空图。
- `npm audit --omit=dev`：0 vulnerabilities。

可复现基准：固定种子随机 800×800 RGBA、附件 220 色、Floyd–Steinberg 抖动、上限 32 色。Node 映射内核测得 50×50 约 177ms、100×100 约 653ms，不含 Worker Blob 解码与裁剪。100×100 双色棋盘、25×25 工作区的路线在大色面/少换色/少移动模式测得约 44/56/73ms。此结果证明桌面内核达到 1 秒/2 秒级目标，未声称低端手机或极大原图也达到相同速度。

浏览器产物在 `test-results`：桌面编辑/工作台/暗色、手机编辑/色卡截图，导出 PNG、CSV、含原图的 JSON 和打印 PDF。此目录不作为应用数据；实际数据在浏览器 IndexedDB。

人工验收清单：相机图片导入、复杂图纸裁剪校正、实物色差校准、目标手机连续拖动/缩放帧率、HTTPS 安装 PWA；这些依赖用户目标设备或实物色卡，不用桌面模拟结果代替。

性能数字会随设备、图片和色板变化。桌面随机图基准用于回归趋势；移动端仍应以目标设备实测为准。
